## Problem and goal

Make the format understandable from a small example, without a team definition or app-specific layout.

## In scope

1. Label a coordinator and a researcher as illustrative standalone agents. Include an agent-owned memory, one shared skill and tool, an unassigned skill, a voice skill with supporting references, and a routine with a separate prompt.
2. Put the tool definition in its own folder and describe how a tool could carry config, code or an external reference. Scope routine participation to that routine only.

## Exclusions

Teams, real agent memories, full-roster migration, live accounts, tool execution and routine activation.

## Acceptance criteria and verification scenarios

1. Give the example alone to an independent reader. They can explain each agent and locate its resources and memories; neither agent requires a team definition.
2. Resolve both agents’ references. They share one skill and one tool; the unassigned skill remains valid and the voice variants are supporting references, not standalone skills.
3. Trace the routine to its prompt and participants, and read the example memory from its owning agent’s folder. Both are understandable without a scheduler or source app.

## Constraints and dependencies

Use synthetic data, no credentials or raw exports. Follow the schema and references in [1](./1.md); this supplies the valid fixture for [6](./6.md).
