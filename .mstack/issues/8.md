## Problem and goal

An agent given one backup instruction and a sanitized OpenBot export can preserve the portable bots and report what it could verify.

## In scope

1. Add a companion skill that inventories readable agents and their resources, writes a new portable package, and reports missing, unsupported and unreadable items rather than silently losing them.
2. Validate the package, then write a root manifest containing each payload path and SHA-256 hash. Keep a trusted copy of the manifest digest outside the backup. Verify the stored copy after creation and again before any use as a restore source.
3. Report completeness, format validity and integrity separately. Keep OpenBot mapping outside the core spec.

## Exclusions

Real account writes, restore or activation, copying credentials or private data into fixtures, running bundled code and modifying the source export.

## Acceptance criteria and verification scenarios

1. An independent operator gives the skill only a sanitized export path and backup destination. The result reports each source agent as captured or skipped with a reason; a fixture with one unsupported item is not reported as complete. The source files remain unchanged.
2. The stored backup passes the offline validator and integrity verification against the separately trusted digest. On disposable copies, adding, deleting or modifying payload files is rejected. Substituting the manifest alongside altered files is rejected by the trusted digest check.
3. Without a trusted digest, the skill reports integrity as unverified, not passed. Verification does not launch a restore.

## Constraints and open decisions

Use a sanitized fixture before any real data. Keep verification offline after capture. Manifest serialization and trusted digest storage location must be specified before implementation readiness.
