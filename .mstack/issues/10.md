## Problem and goal

During a real cold-start CLI backup test (a fresh Claude Code session pointed at `mikemajara/agent-files`), the agent discovered `skills/agent-files/SKILL.md` and `references/cli.md` cleanly, but stalled trying to file-by-file audit and copy ~70+ machine-wide user-global skills (`~/.claude/skills/`, `~/.agents/skills/`, etc.) before ever writing `agent.json`, `instructions.md`, `tools.md`, `routines.md`, or `gaps.md`. In addition, `SKILL.md` and `README.md` do not yet explicitly forbid writing backup outputs inside the `agent-files` specification repository itself.

Update the skill, harness reference notes, and README so that:
1. Machine-wide / user-global skills are bundled only when explicitly requested by the user (and otherwise recorded in `gaps.md`), while agent-assigned or workspace/project-scoped skills are captured by default.
2. Backups are never written inside the repository holding the Agent Files specification and skill.

## In scope

1. **Opt-in global skills & capture order (`skills/agent-files/SKILL.md`, `skills/agent-files/references/cli.md`, `skills/agent-files/references/openbot.md`):**
   - In `SKILL.md` (harness-agnostic): capture only skills explicitly assigned to the requested agent(s) or scoped to the agent/project workspace by default; bundle machine-wide or user-global shared skill libraries only when explicitly requested by the user, and record unbundled global skills as an explicit gap in `gaps.md` (using `"skills": []` when the agent has no assigned/project skills and logging the unbundled global catalog in `gaps.md`). Write the agent's core files before copying bulk skill folders so core agent definitions are always captured cleanly.
   - In `references/cli.md` and `references/openbot.md`: align skill lookup guidance so user-global / machine-wide skill directories (`~/.agents/skills/`, `~/.claude/skills/`, `~/.codex/skills/`, etc.) and shared OpenBot libraries are treated as opt-in unless explicitly requested, rather than auto-copied by default.
2. **Spec-repository write guardrail (`skills/agent-files/SKILL.md`, `README.md`):**
   - Explicitly forbid writing backup outputs inside the repository that hosts the Agent Files specification and skill itself; always write to a separate local folder or a separate backup repository.
3. **Cold-start CLI capture verification:**
   - Run a fresh cold-start CLI agent (`claude -p --no-session-persistence`) in a disposable empty local folder pointed at the updated skill with a single bare backup prompt, verifying it completes autonomously without stalling, captures the core Agent Files layout, skips global skills by default while logging them in `gaps.md`, leaks zero secrets, and leaves `mikemajara/agent-files` untouched.

## Out of scope

1. Changing the six shared concepts or the three-state presence model in `SPEC.md`.
2. Deterministic converters, validators, scripts, Node packages, or synthetic fixtures.
3. Creating or pushing to remote backup repositories as part of automated verification.

## Constraints

1. Keep `skills/agent-files/SKILL.md` strictly harness-agnostic; harness-specific global skill paths belong only under `skills/agent-files/references/`.
2. Never include secrets, credentials, tokens, personal memories, or personal machine paths in the repository or PR artifacts.

## Acceptance criteria

1. **Opt-in global skills & capture ordering:** `skills/agent-files/SKILL.md` explicitly scopes default skill capture to agent-assigned or agent/project-scoped skills, requires explicit user request before bundling machine-wide/global skills (recording unbundled global skills in `gaps.md`), and directs writing core agent files cleanly without stalling on bulk skill libraries. `references/cli.md` and `references/openbot.md` align with this rule and contain zero personal paths or secrets.
2. **Spec-repository guardrail:** `skills/agent-files/SKILL.md` and `README.md` explicitly state that backups must never be written inside the `agent-files` spec/skill repository itself (always target a separate local folder or separate backup repository).
3. **Cold-start CLI autonomous backup succeeds:** A fresh cold-start Claude Code CLI agent (`claude -p --no-session-persistence`) in a disposable empty local folder pointed at the branch's `skills/agent-files/SKILL.md` with a single bare prompt completes autonomously within a single run, writes a valid Agent Files bundle (`agent.json`, `instructions.md`, `tools.md`, `routines.md`, `gaps.md`, plus `memories.md` or memory gap) with all references resolving inside the bundle root, does not bundle machine-wide global skills by default while recording them in `gaps.md`, leaks zero secrets, and leaves `mikemajara/agent-files` untouched.
