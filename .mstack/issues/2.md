## Delivery scope

Broad inventory and migration follow-up. v0.1 story [3](./3.md) reads/reconciles only its selected example sources; completing this whole inventory is not a prerequisite for the first package.

The maintained knowledge selected for an agent has a traceable source; a separate reusable role layer is not assumed. The remaining detailed criteria below are retained for later refinement and do not gate v0.1.

## Problem and goal

Account for the useful skills and reusable baseline knowledge split across shared, Mai and installed local sources before migration.

## In scope

- Compare GitHub heads, local working trees and installed sources, including supporting resources.
- Record each skill’s provenance, differences and proposed retain/merge/retire disposition.
- Inventory baseline knowledge embedded in agent instructions or referenced documents; distinguish reusable maintained knowledge from memories, history and project-specific assignments. Record ownership/source and whether each resource can be bundled or needs external access.
- Migrate the selected shared packages once their differences are resolved, starting with task-management and work-review.

## Acceptance criteria

1. Every discovered source skill has a disposition and source identity; local-only changes are accounted for.
2. Task-management and work-review retain the selected behavior and all referenced resources.
3. The original repositories and working-tree edits remain intact.
4. Knowledge selected for the first role has a traceable maintained source and an explicit bundle/reference disposition; runtime memories are not promoted into role knowledge by default.

## Verification scenarios

1. **AC 1** — Enumerate source packages and compare them with the inventory; verify every package and changed supporting file is covered.
2. **AC 2** — Load each migrated SKILL.md, resolve its local references and compare the selected behavior with the recorded source differences.
3. **AC 3** — Compare source working-tree status and relevant file content before and after transfer; explain any concurrent external changes.
4. **AC 4** — Trace each selected knowledge resource to its maintained source, inspect the selected content or access requirement, and confirm its disposition does not export runtime memory or history.

## Constraints

Preserve existing Mai code and source edits. Store portable definitions without agent runtime state or credentials. This story is a draft; unresolved decisions below must be settled before implementation readiness.

## Findings and open questions

Select the authoritative content where copies diverge. Assess conversation, Slack-specific and test skills individually; do not copy Mai runtime machinery merely to preserve skills.
